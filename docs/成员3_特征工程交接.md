# 成员3交接：特征工程与消融实验

本交接文档于 2026-10-17 修订。核心结论：新增并保留 `CabinZone`（舱号区间分箱），
弃用连续 `CabinNum` 与 5 个组内聚合特征；最终建模矩阵由 53 列变为 59 列。



在现有 53 列特征的基础上，唯一值得新增的特征是 **CabinZone（舱号区间分箱）**：
它对树模型带来约 +1 个百分点的稳定提升（5 折配对、5/5 折为正、p≈0.01）。
其余候选特征（连续 CabinNum、组内年龄/消费聚合）要么有泄漏风险、要么无贡献，已否决。

## 实验方法与固定设置

- 数据入口：`build_features_combined(train_raw, test_raw)`，人数计数合并 train+test 计算。
- 折划分：统一使用 `features/folds.csv`（按 GroupId 的分层分组 5 折，seed=42），**未做任何重新切分**。
- 每折独立拟合填补器：`pp.prepare_fold_matrices(features, tr_idx, va_idx, strategy="rule_group")`。
- 固定模型：
  - HistGB：`HistGradientBoostingClassifier(learning_rate=0.08, max_iter=200,
    max_leaf_nodes=31, l2_regularization=1.0, early_stopping=False, random_state=42)`
  - LogReg：`StandardScaler + LogisticRegression(max_iter=2000, C=1.0, random_state=42)`
- 评价：准确率（Accuracy），5 折均值 ± 标准差。

> 方法学提醒：上述 HistGB 默认 `max_features=1.0` 且无 bootstrap，LogReg 用 lbfgs，
> 两者在本配置下都是**确定性模型**。因此"多个随机种子重复"是伪重复，
> 真实方差只来自 5 折划分；显著性判断使用 5 折配对 t 检验（df=4）。

## 现有特征的分组消融

把 59 列按语义分成 5 组：基础（原始字段+Deck/Side 拆解）、舱位（CabinZone）、
群组（GroupSize/Surname 等）、消费派生、年龄派生。结果见
`reports/experiments/feature_group_ablation.csv`。

| 特征集 | HistGB | LogReg |
|---|---|---|
| 基础（24 列） | 0.8011 | 0.7891 |
| 基础+舱位（30） | 0.8081 | 0.7949 |
| 全量（59） | 0.8113 | 0.7954 |
| 全量-舱位（53） | 0.8011 | 0.7943 |
| 全量-消费（45） | 0.8070 | 0.7966 |
| 全量-群组（53） | 0.8115 | 0.7954 |

要点：舱位组（CabinZone）是本次唯一的稳定增量；消费派生对线性模型贡献最大；
群组组对两个模型都几乎没有边际贡献；年龄组贡献很小。以上与成员2 的结论一致。

## 新候选特征的逐个检验

以旧 53 列为基线，对每个候选特征做"基线 vs 基线+该特征"的 5 折配对检验，
结果见 `reports/experiments/feature_additions.csv`。

| 候选特征 | HistGB 相对基线 | 正折数 | 配对 p 值 | 结论 |
|---|---|---|---|---|
| +CabinZone | +0.0102 | 5/5 | 0.0116 | 保留 |
| +CabinNum | +0.0100 | 5/5 | 0.0124 | 否决（见下方指纹核查） |
| +GroupMeanAge | +0.0002 | 1/5 | 0.9111 | 否决 |
| +GroupAgeSpan | +0.0003 | 1/5 | 0.8877 | 否决 |
| +GroupHasChild | -0.0008 | 2/5 | 0.6459 | 否决 |
| +GroupTotalSpend | +0.0014 | 3/5 | 0.5339 | 否决 |
| +GroupHasSpender | +0.0007 | 2/5 | 0.8210 | 否决 |

LogReg 下的趋势相同但幅度更小（CabinZone 约 +0.10 个百分点，组聚合无贡献）。

## CabinNum 的指纹核查 

`CabinNum` 与 `CabinZone` 的 CV 增益几乎相同（都约 +1pp，二者信息高度重叠），
但对抗验证显示二者风险不同：

| 特征组合（区分 train/test 的 AUC，应≈0.5） | AUC |
|---|---|
| Deck+Side | 0.5027 |
| CabinZone | 0.4960 |
| CabinNum | 0.5343 |
| Deck+Side+CabinNum | 0.5786 |
| Deck+Side+CabinZone | 0.5045 |

结论：连续 `CabinNum` 带有 train/test 分布差异（轻微数据集指纹），
而分箱后的 `CabinZone` 对抗 AUC 干净（0.496）且提供同等增益。
因此在已有 CabinZone 的 64 列上再增 CabinNum 仅 +0.17pp（p=0.35，不显著）。
**最终保留 CabinZone，弃用 CabinNum。**

## 最终特征方案

- 保留：成员2 的 53 列 + `CabinZone` 的 6 个 one-hot 列，共 **59 列**。
- 弃用：`CabinNum`（连续舱号，指纹风险）、`GroupMeanAge`、`GroupAgeSpan`、
  `GroupHasChild`、`GroupTotalSpend`、`GroupHasSpender`（组内聚合，无贡献）。
- 缺失标记：本次独立复现（`scripts/check_missing_marker.py`，结果见
  `reports/experiments/missing_marker_recheck.csv`）：LogReg 下 S3（简单填充+指示位）
  0.7957 与 S2（简单填充）0.7958 几乎相同，HistGB 下 S3 0.8105 反而略低于 S2 0.8124，
  均为噪声量级。缺失指示位不作为新增特征方向。

代码落点：`src/preprocess.py` 新增 `add_cabin_zone_features`，
`CAT_FEATURES` 加入 `CabinZone`；`scripts/export_features.py` 的特征说明同步更新。
`features/train_clean.csv`、`test_clean.csv`、`feature_dict.md` 已重新导出；
`features/folds.csv` 保持不变。

## 给建模成员的注意事项

1. 正式 CV 仍按 `folds.csv` + `prepare_fold_matrices` 逐折拟合填补器，不要在
   `train_clean.csv` 上直接切五折。
2. 最终全量训练直接使用新的 `features/train_clean.csv`（已含 CabinZone）或
   `export_features` 重新导出；测试预测对应使用 `test_clean.csv`。
3. CabinZone 对树模型（CatBoost 方向）的价值显著，对线性模型较小；
   若成员1 使用 CatBoost 原生类别输入，可将 CabinZone 作为类别特征直接使用。
4. 不要回退使用连续 `CabinNum` 入模——它的增益与 CabinZone 重叠且有指纹风险。
