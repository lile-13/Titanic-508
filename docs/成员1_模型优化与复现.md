# 成员1：模型优化与复现

实验目录：`reports/experiments/optimization_20261025/`。本轮从原始比赛数据重新构建特征，不覆盖成员2、3、4的历史实验文件。

## 验证约定

保留团队原有的 `features/folds.csv`，同行 GroupId 不跨折。第1～4折用于开发，每次用其中3折训练、1折验证；第5折的标签既不用于这些训练，也不用于特征、参数、种子、融合权重或阈值选择。

第5折在历史基线实验中已经被查看，因此它是本轮保留的确认折，不能称为从未查看过的盲测集。开发折的训练样本比原五折实验少，不能把本轮开发分数直接与旧五折均值相减来宣称提升；本轮另跑相同开发划分的固定参数CatBoost作为基线。

公开train与test的无标签特征统一构建群组和姓氏计数，避免分别统计SurnameSize造成数据集来源指纹。填补器只在当次训练分区拟合。Transported、PassengerId不进入模型，组内类别传播仅限HomePlanet和Side。

## 搜索范围

| 内容 | 本轮设置 |
|---|---|
| 特征/预处理组合 | 9种，基础、舱位、消费、组统计、姓名及缺失保留对照 |
| 输入规模 | 基础方案30列；候选方案40～81列；不是原one-hot接口的59列 |
| 特征方案筛选 | 先开发折1、2；每个模型家族排名前三的方案再做全部4个开发折 |
| CatBoost参数搜索 | 32组确定性随机配置，深度、学习率、正则、采样与类别统计复杂度 |
| LightGBM参数搜索 | 48组确定性随机配置，叶子数、学习率、叶节点样本量、正则与采样 |
| 迭代次数 | 开发期仅用开发验证折早停；入围后取4折最佳轮数的中位数并固定 |
| 种子复核 | 入围的2个CatBoost方案与1个LightGBM方案各用42、2026、103，不再早停 |
| 融合/阈值 | 权重按0.25步长，阈值0.45、0.475、0.5、0.525、0.55；只在开发折选择 |

部分LightGBM配置没有随机采样，换随机种子会得到相同预测，不能把这种重复训练当作额外独立证据。

`rich`等候选重新实现了连续舱位、组统计与姓名信息，用于当前模型的独立实验，不是对成员3旧候选脚本和旧分数的复现。是否保留由本轮同折结果决定，不能因为旧HistGB实验否决了某特征，就推断它对所有模型都无效。

## 冻结与确认

选择完成后先写 `frozen_plan.json`，锁定成员模型、特征、轮数、种子、融合权重和阈值，再用开发集全部4折训练并评估第5折。预先规定的候选生成条件为：

1. 开发准确率相对本轮固定CatBoost基线至少增加0.003。
2. 固定方案在确认折的准确率不低于旧CatBoost同一折减0.003。

确认折评估后不再据此改参数、权重或阈值。如果未通过，保留原有CatBoost候选，并如实记录搜索未获可靠新方案。通过仅表示生成新候选，不代表已经证明它优于原模型；最终推荐结合各折表现、确认差异的不确定性和真实榜分。

通过后按原团队五折重训冻结方案，平均5个训练分区的测试概率，保存完整模型。此时第1～4折参与过模型选择，最终OOF均值属于选择后的描述性结果，不能称为无偏泛化估计，更不能当作Kaggle榜分。

## 运行命令

从仓库根目录执行，数据文件应位于 `data/raw/`。名称相同会复用已完成试验；若搜索实现或原始数据改变，应使用新的 `--name`，防止混合实验。

```powershell
# 可依次执行，也可在不同终端运行两个家族；每个进程限制为4线程。
.\.venv\Scripts\python.exe -m scripts.optimize --phase search --family catboost --trials 32 --threads 4
.\.venv\Scripts\python.exe -m scripts.optimize --phase search --family lightgbm --trials 48 --threads 4

# 两个家族搜索完成后：固定选择、确认第5折，通过后保存候选与模型。
.\.venv\Scripts\python.exe -m scripts.optimize --phase finalize --threads 4

# 校验所有搜索记录均未对第5折打分；有新模型时还会独立重载并复现测试概率。
.\.venv\Scripts\python.exe -m scripts.verify_optimization

# 生成训练/验证差距、测试预测差异与可供报告引用的结果摘要。
.\.venv\Scripts\python.exe -m scripts.diagnose_ensemble
.\.venv\Scripts\python.exe -m scripts.summarize_optimization

# 仅在生成ensemble.joblib后执行；输出目录已存在时请换一个新目录。
.\.venv\Scripts\python.exe -m scripts.predict_ensemble --bundle models/optimization_20261025/ensemble.joblib
```

`scripts.search_worker`可在主进程完成三个Profile后补算确定性搜索计划的尾部任务。它调用原搜索函数生成相同配置，再反序执行指定区间；不增加额外试验或改变选择规则。通常直接用上面的顺序命令即可复现。

## 产物与证据

- `protocol.json`：分区、替换条件、数据与核心优化源码SHA256。
- `environment.json`、`dependency_hashes.json`：运行版本及预处理/折划分依赖快照。
- `feature_profiles.csv`、`feature_audit.json`：输入规模、标签独立性检查。
- `adversarial_profiles.csv`、`adversarial_protocol.json`：数据集来源识别的诊断；设置不同，不能直接与成员2旧AUC比较。
- `trial_*.json`、`trials_all.csv`：逐次配置、各折分数、最佳轮数、耗时与是否早停。
- `frozen_plan.json`、`confirmation_result.json`、`final_summary.json`：冻结选择与确认结果。
- 通过确认后：本目录的 `oof_predictions.csv`、`fold_metrics.csv`；本地 `outputs/optimization_20261025/`中的测试概率和提交CSV；本地 `models/optimization_20261025/ensemble.joblib`中的完整模型。
- `reports/checks/optimization_20261025.json`：原始数据、乘客/折顺序、OOF指标、权重之和及模型重载预测的检查结果。

models和outputs按既有.gitignore保留在本地。代码、实验摘要与报告证据可随项目分享，队友需自行下载比赛数据。尚未进行Kaggle提交时，不填写榜分或名次。
